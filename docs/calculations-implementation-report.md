# 備蓄計算・手動保存・履歴の実装結果

2026年11月12日（JST）。コードと自動検証を追加。実ブラウザ検証待ち。

## 操作と結果

避難所一覧・避難所編集・倉庫対応画面から備蓄計算へ進む。
`/calculations` では避難所の正式目標を初期表示し、試算人数・日数だけを変更できる。
計算は登録済み需要全件を対象とし、正式目標更新と結果保存を発生させない。
必要量・算入量・充足量・不足量・調達目安・充足率・人数・日数・制約需要を表示する。
異なる需要の数量は合計しない。主要結果は常時表示、基準・出典・品目換算・倉庫対応・在庫根拠は展開式。

基準日は実行時のJST当日、期限当日は有効。期限切れ・削除済み・統合元を算入しない。
登録終了品目の既存在庫は明示した需要へ換算する。専用は全量、共有は選択避難所への割当分のみ。
期限未確認は実際の算入量が正の場合だけ暫定警告とし、それだけでは計算不可にしない。
期間内期限到来は両端を含めた注意とし、消費や補給の予測は行わない。

設定完了の対応倉庫0件・共有割当0は正常な数量0。
専用倉庫の需要別在庫未登録、設定中、帰属矛盾、基準・換算・根拠不足は理由付き計算不可。
確認できた数量は参考量に分ける。一部不可でも計算200で返し、総合人数・日数はnull、全制約フラグはfalse。
全需要計算可能な場合は最小人数・日数を表示し、同率を含む全制約需要を示す。

「この結果を保存」で部分不可を含む計算時点の主要根拠を6表に一括保存する。
保存前に在庫・名称・目標・基準等が変わっても現値で再構築せず、計算日時と保存日時を分ける。
同一トークン・同一訂正元の再送は保存済み結果を返し、異なる訂正元の再送は拒否する。
保存履歴は避難所・計算日時・結果状態で絞り込み、日時降順・ID降順に20件ずつ表示。
詳細は保存6表を使い、訂正元・訂正先へ移動できる。訂正は元結果を変更せず新しい計算として保存する。
入力エラー・通信失敗では入力と前回結果を保持し、自動再送しない。

## APIと保存境界

すべて `/api/v1` 配下。IDは文字列、人数・日数はJSON整数、数量は十進文字列。

| 操作 | パス | 成功 |
| --- | --- | --- |
| 一時試算 | POST /calculations | CalculationPreview、200 |
| 凍結結果の再取得 | GET /calculations/{calculation_token} | CalculationPreview、200 |
| 手動保存 | POST /calculation-runs | SavedCalculation、初回201＋Location、同一保存再送200 |
| 履歴 | GET /calculation-runs | Run配列とpage、200 |
| 保存詳細 | GET /calculation-runs/{run_id} | SavedCalculation、200 |

試算本文は `{"shelter_id":"1"}`、または `target_people` と `target_days` を両方指定。
保存本文は `{"calculation_token":"...","correction_of_run_id":null}`。訂正元は省略可能。
履歴の任意クエリーは `shelter_id,result_state,from,to,limit,offset`。
日時はUTCの `YYYY-MM-DDTHH:mm:ss.SSSZ`、fromを含みtoを含まない。
画面の検索日時入力は端末時間帯と明記しUTCへ変換、結果日時は日本時間で表示する。

読取BEGINで条件と主要数量を同じ時点から確保し、DBトランザクションを終了してからメモリーに保持する。
凍結物は不変の文字列、ランダムトークンは256bit。固定TTLなし、アプリごとに独立、再起動で喪失する。
未保存の永続ドラフト、複数サーバープロセス間共有は提供しない。

保存時はダイジェスト、集合の重複・参照、算術結果・理由・警告の再評価一致を検証する。
現マスターから根拠を引き直さず、BEGIN IMMEDIATEでMAX(run_id)+1と訂正元を検証。
需要→品目→倉庫→全対応先→在庫→ヘッダーの順にINSERTし、件数を照合、遅延FKを含めCOMMITする。
失敗時は全ROLLBACKし、トークンを未保存のまま保持。トークンごとのロックで同時保存を直列化する。
時計逆行で保存日時が計算日時より前なら、計算日時を改変せず失敗を返す。
