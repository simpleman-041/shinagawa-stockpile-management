# UI改善と演習データの登録記録

2026年11月23日確認。通常DBに公開倉庫情報を登録した記録と、今回の座標追加・架空データ整理の結果を示す。

## 倉庫座標の登録と架空データの整理

- 通常DBは倉庫29件。確認済みの座標2件を保持し、26件の座標を追加・訂正した。大崎備蓄倉庫は公開住所に訂正し、大井1丁目備蓄倉庫は公開住所と一致する座標に訂正した。
- 住居表示が照合できる24件は、国土地理院の品川区・大田区CSVの2026-03-26版にある基礎番号の代表点。戸越、大崎西口公園内、西品川一丁目の3件は、公開資料で併設先を確認してからその住居表示を照合した。座標は小数第6位に丸めた。 [国土地理院の住居表示住所](https://www.gsi.go.jp/kihonjohochousa/jukyo_jusho.html)
- 八潮22号棟は所在地と棟名が一致する公開地図の位置、八潮38号棟は公開地図の建物形状の重心を採用した。旗の台3丁目備蓄倉庫は街区まで確認できたため、地図上の位置は未登録とした。 [八潮22号棟](https://map.yahoo.co.jp/v3/place/IX0lOkkRwO-) · [八潮38号棟 © OpenStreetMap contributors](https://www.openstreetmap.org/way/162938037) · [投入用台帳](../data/demo/shinagawa-stockpile-catalog.json)
- 承認を得た架空の「品川倉庫」1件は、通常DBのバックアップ作成と参照レコードの確認を行って削除した。倉庫保持用トリガーを同じトランザクション内で復元し、スキーマの一致と外部キーの整合性を確認した。前回の演習DBは、架空在庫8件と関連する架空の設定・履歴を含めて、起動で指定していた名前からバックアップ名に退避した。
- 既存の大崎・大井1丁目の容量値は、元の運用値かどうか判別できなかったため保持した。今回の座標は施設や住所の代表点で、倉庫入口や屋内位置を示す精度の現地測量は未実施。

以下は、座標追加と架空データ整理を行う前の初回登録・UI改善の記録。

## 登録先と演習の範囲

| DB | 実施した登録 | 再実行 |
|---|---|---|
| `instance/unfire.sqlite3` | 倉庫27件を追加し、3件から30件になった。大崎備蓄倉庫と大井1丁目備蓄倉庫は既存と照合して追加を見送り、既存3件の属性を保持した | 同じ入力で追加0件 |
| `instance/stockpile-demo.sqlite3` | 実在倉庫29件と架空の容量検証倉庫1件、公開資料の品目13件と架空の容積箱1件、架空在庫8件。演習用の入庫履歴7件、担当者1件、避難所2件、対応・割当・計算基準を含む | 同じDBでは追加0件。入出庫・設定の変更後も初期値に戻さない |

倉庫の公開情報を通常DBに追加するコマンド。既存行と倉庫名または住所が一致した場合は、照合結果を出力する。

```powershell
.\.venv\Scripts\python.exe -m tools.seed_stockpile --database .\instance\unfire.sqlite3
```

当時の演習用投入では、空の初期化済みDBに `--demo` を付けて実行した。品目登録に必須の期限接近7日、単位の分割可否、在庫数量、期限、保管場所、担当者、避難所、対応・割当、目標・換算・使用基準は演習設定。架空の施設・品目だけに容量・容積を設定した。通常DBへ品目も登録するには、品目ごとの期限接近判定日数と分割可否の確認が必要。

投入は既存スキーマと外部キーを使い、1回の書き込みトランザクションで確定する。投入途中に失敗した場合は全体をロールバックする。アプリ起動と投入は別操作。スキーマとAPI・業務計算の仕様を維持した。

## デモで確認できる状態

- 荏原備蓄倉庫のアルファ化米は、通常600食、期限接近60食、期限切れ100食。演習避難所Aの計算には期限切れ100食を含めず、660食を算入する。
- 飲料水は荏原の450 Lと大井のA向け割当100 Lで550 L、目標600 Lに50 L不足する。荏原へ50 Lを入庫後に再計算すると、飲料水が600 Lとなり、総合の支援可能人数は100人となる。大井の共有在庫200 LのうちB向け50 LはAに算入しない。
- 大井備蓄倉庫のアルファ化米は登録済みの数量0。毛布は在庫未登録。地図で荏原または大井の容量計算不可を確認できる。座標未確認一覧で「演習用容量検証倉庫（架空）」を選ぶと、容量1 m³に対し使用量2 m³の容量超過を確認できる。
- 期限は投入時の日本時間を基準に設定する。再投入で期限を動かさないため、後日に期限接近を再現するときは別の空の演習DBを使う。
