# 入出庫の実装・検証結果

2026年11月12日（JST）。状態：実装済み・実ブラウザ検証待ち。

## 利用者の操作と採用仕様

倉庫一覧の「在庫を見る」→在庫の「詳細を見る」から、入庫・出庫・履歴検索・確認付き取消を操作できる。
数量・担当者・任意理由を指定して入出庫を登録すると、現在庫と履歴を一括保存し、取引ID付きの成功表示と更新後の値を表示する。
担当者は事前登録一覧から選択し、登録日時と担当者名の写しをサーバーで記録する。
履歴は区分・状態・日本時間の開始／終了日時で検索でき、20件単位でページを切り替える。期間の終了は含まない。

取消は対象の元取引と現在庫・割当を再取得して確認画面に表示し、取消担当者と確認チェックを指定して実行する。
元取引の登録内容は保持し、取消担当者ID・氏名と日時だけを追記する。取消の逆取引は作らない。
エラー・通信失敗時は入力を保持し、POSTを自動再送しない。「現在庫・履歴を再取得」で結果確認できる。

依頼者が本会話で承認した [実装方針](movements-implementation-plan.md) に従う。
採用資料は要件書2.0（F04・F05、§5.1、Q04・08〜10・15・17・51〜53）、DB設計・DDL 2026-11-01（TX01・TX02）、API設計1.0（MV01〜04）。
画面S004の任意処理日入力、倉庫・品目名による独自の履歴検索は、承認どおり要件・APIを優先して実装しない。

## APIと変更ファイル

接頭辞は `/api/v1`。本文はUTF-8の`application/json`。ID・数量は文字列。

| API | 操作 | 成功 |
| --- | --- | --- |
| MV01 | GET /stock-movements | Movement配列、page、200 |
| MV04 | GET /stock-movements/{movement_id} | Movement、200 |
| MV02 | POST /stocks/{stock_id}/movements | MovementResult、201、個別参照先のLocation |
| MV03 | POST /stock-movements/{movement_id}/cancellation | 元MovementをcancelledにしたMovementResult、200 |

登録本文は`{"kind":"out","quantity":"2","operator_id":"1","reason":null}`、取消本文は`{"operator_id":"1"}`。
理由は省略可能。独自の確認フラグを取消APIへ追加せず、画面側で確認を行う。
一覧クエリーは`stock_id,state,kind,from,to,limit,offset`。APIの既定件数50、最大200、登録日時降順・同時刻はID降順。
日時境界はUTCの`YYYY-MM-DDTHH:mm:ss.SSSZ`。24:00の翌日への暗黙補正も拒否する。

DB接続は既存`get_db`を共用する。更新は検証から数量・履歴更新まで単一接続の`BEGIN IMMEDIATE`、参照は`BEGIN`。
外部キー・再帰トリガーを既存経路で有効化し、途中失敗・COMMIT失敗を全ロールバックする。
割当は自動変更しない。保存済み計算への更新はない。
共通入口への変更はBlueprintと404・405の対象パス追加に限定した。
DBスキーマ、依存関係、マスター画面、割当編集、容量集計、計算、認証・権限管理、担当者管理は対象外。
これらの隣接APIを実装済みとして画面から呼び出す処理は追加していない。

## 実行結果と制限

プロジェクトルートで次を実行した。

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
node --check app/static/js/stocks.js
node tests/stocks-movements-ui.test.cjs
```

pytestは259件成功、失敗・エラー・スキップ0件（既存194件＋追加65件）。Nodeの動作検証は2件成功、失敗0件。JavaScript構文確認も成功。
Python 3.15.2、SQLite 3.53.4、pytest 9.2.0を使用した。
最初のsandbox内pytestは一時フォルダへのアクセス拒否、`node --test`は子プロセス起動のEPERMで失敗した。
pytestは権限付きで検証専用一時DBを使って実行し、Nodeは子プロセスを使わない上記コマンドで実行した。
開発DBは検証に使用・更新していない。初回追加テストで検出した24:00受理は修正後の全体実行で成功した。

Microsoft Edgeの手動確認を試みたが、ブラウザアクセスホストが利用できず、ネイティブEdge起動も`Computer Use app approval timed out`で停止した。
検証用の架空DBサーバーを用意したが、実ブラウザでは表示・操作を確認できていない。試験サーバーは停止した。
DOM代替テストとJinja2応答テストで、実ブラウザのレイアウト・入力制約・モーダル動作を確認済みとはしない。

実ブラウザで正常登録・空結果・数量不足の拒否・通信失敗と入力保持・取消確認・ページ送りを確認し、人間の独立レビューを行う必要がある。
そのため実装完了・受入完了とは報告せず、「実装済み・実ブラウザ検証待ち」とする。仕様確認待ちの事項はない。
